# DECISIONS

Architecture decisions and every deviation from MASTER_PROMPT, with reasons.

## Fixed architecture (§2)
1. **Web on Vercel only.** OpenCV, MediaPipe, librosa, onnxruntime and ffmpeg exceed Vercel serverless bundle and execution limits, so the ML engine runs as a Docker Space on Hugging Face and is called only from Vercel server routes carrying `X-Engine-Secret`.
2. **Uploads bypass Vercel.** Vercel function bodies are capped at ~4.5 MB. The browser uploads straight to Supabase Storage through a signed upload URL; the engine downloads with the service-role key.
3. **Asynchronous jobs.** `POST /analyze` returns 202. The engine writes `case_events` rows and updates `cases.status`; the browser subscribes with Supabase Realtime. A single 5 s poll runs only if the Realtime channel reports `CHANNEL_ERROR`/`TIMED_OUT`.
4. **Cold start is surfaced.** The analyze page pings `/api/engine/health` (a thin Vercel proxy to the Space `/health`) and shows "Engine waking up · Ns" until it answers.
5. **Models are data.** The engine reads `is_active` rows from `model_registry` at startup, downloads their files (reassembling chunked files from `manifest.json`), verifies SHA-256 and caches them under `MODEL_CACHE_DIR`. Publishing a new version and restarting the Space (or calling `POST /models/reload`) updates the live site without a redeploy.
6. **Secrets.** Groq key and Supabase service-role key exist only in Vercel server env and HF Space secrets. Only `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY` and `NEXT_PUBLIC_SITE_URL` are public.

## Deviations and resolutions
1. **Design reference not attached.** The "Jack — 3D Creator" spec was not included with the prompt. §8 was implemented from every concrete token the prompt gives (colors, Kanit/JetBrains Mono, `.hero-heading` gradient, ContactButton gradient/inset/outline, ghost LiveProjectButton, motion ease, component names and behaviors). Exact pixel sizing and whitespace rules of the original spec (hero heading clamp, About corner offsets) are reasonable reconstructions and should be reconciled against the spec in a targeted pass.
2. **Groq default model = `openai/gpt-oss-120b` (not verified in this build).** The prompt asks to check Groq's current model list; web search returned no usable result and api.groq.com was not reachable from the build sandbox, so the list could not be checked. `openai/gpt-oss-120b` is used as the default because it was a Groq production model supporting JSON mode as of the model's training data. RUN_GUIDE §4 tells you to confirm it at console.groq.com/docs/models; `GROQ_MODEL` overrides it without code changes.
3. **Face CNN = DeepfakeBench EfficientNet-B4 (`effnb4_best.pth`, release v1.0.1, URL and byte size verified).** The network definition was checked against `SCLBD/DeepfakeBench/training/networks/efficientnetb4.py`: `efficientnet_pytorch` EfficientNet-B4 with a plain 3×3/2 `Conv2d` stem (no padding), `_fc = Identity`, `last_layer` Linear(1792→2), fake probability = softmax[:,1]; input 256×256, mean/std 0.5. `training/` therefore uses `efficientnet_pytorch`; timm and torchvision from the §3 stack list are not needed by any stage and are not installed. The CAM is average-pooled to 8×8 inside the graph so its size does not depend on the stem's padding arithmetic.
4. **AASIST-L model code is vendored** (`training/models/aasist.py`, MIT, NAVER Corp., unchanged) because the published weights require the exact module tree for loading and ONNX export. Input is fixed at 64 600 samples (≈4.04 s at 16 kHz) because the spectral positional embedding has 23 nodes; "4-second windows" therefore means 64 600-sample windows with 32 300-sample hop.
5. **UnivFD = OpenAI CLIP ViT-L/14 image tower exported to ONNX + linear probe JSON** (`fc_weights.pth` from Yuheng-Li/UniversalFakeDetect, verified). CLIP weights are fetched by `open_clip` from its own registry at export time; no CLIP URL is hardcoded.
6. **Export tooling in the backend venv.** `fetch_pretrained.py` must build ONNX graphs with PyTorch, which is not part of the slim runtime image. It uses `backend/requirements-export.txt` (CPU torch, efficientnet_pytorch, open_clip) installed only on the developer machine; the Docker image never contains torch.
7. **Temporal window.** §5.2 asks for a 2-second dense window but rPPG requires ≥5 s. The engine instead streams the whole (duration-capped) clip at ≤15 fps storing only landmarks and ROI colour means (a few KB per frame), which satisfies blink, jitter, rPPG and AV-sync together; the 32 uniformly sampled frames still drive the per-frame CNN timeline.
8. **Indicator → score calibration.** Each indicator emits raw `features`; `score_0_1 = sigmoid(b + Σ a_k·f_k)`. Before training, documented literature-based defaults are used and marked `calibrated:false`; `train_fusion` fits these per-indicator calibrators and they ship inside the fusion JSON.
9. **Calibration method = Platt/temperature scaling, not isotonic.** Isotonic regression would break the requirement that modality contributions are exact. With `p = σ(α·z + β)` every contribution is exactly `α·wᵢ·xᵢ` in calibrated log-odds.
10. **Validation split usage.** The validation split is divided deterministically by group (seeded, balanced by item count) into fold A (fusion + indicator calibrator fitting) and fold B (Platt scaling, thresholds, reliability curve). Test is used only by `evaluate`. `handcrafted_features` therefore runs on validation **and** test.
11. **Training command path.** §5.6 runs from the repo root (`--data ./datasets`) while §14.7 runs from `training/`. `py -m training.run_all` only resolves from the repo root, so RUN_GUIDE uses the repo root with the venv at `training/.venv`.
12. **Middleware location.** With a `src/` directory Next.js only loads `src/middleware.ts`; it lives there.
13. **Instanced upright cards in the Dome Archive.** drei `<Billboard>` wraps individual meshes and cannot orient instances of an `InstancedMesh` (needed for 300 smooth cards). The camera stays at the dome centre, so each instance is oriented with a world-up `lookAt` toward the dome axis at its own height; matrices are recomputed every frame while cards re-flow (filters, cluster-by-verdict) and are static otherwise. Text never rolls or mirrors. Atlas cells are 200 px so 300 cards fit a 3600 px texture (under the common 4096 px limit).
14. **Live chunk cleanup = engine sweep.** Supabase cron cannot delete Storage objects without pg_net + service key inside SQL. The engine deletes `live-chunks` objects older than 24 h on startup and hourly.
15. **Artifact URLs.** Buckets are private, so indicators store a Storage path in `evidence_artifact_url`; the web signs it on demand (`/api/artifacts/sign`, ownership checked by user-id prefix).
16. **Chat streaming with JSON mode.** The chat route streams NDJSON (`delta`, `replace`, `done`). Deltas are extracted from the model's streaming `{"answer": ...}` object; after completion the grounding validator runs and, on failure, a single non-streamed regeneration is sent as a `replace` event with `grounding_warning`.
17. **Grounding exemptions.** Integers 0–3, numbers inside hex hashes/UUIDs and ISO timestamps are exempt; derived counts are added to the input JSON as `counts` so they are checked rather than exempted. Probabilities may be restated ×100 (percent) and frequencies ×60 (Hz→bpm).
18. **URL ingest for the public API** uses the same SSRF guard; public API multipart uploads are limited to 4 MB because they pass through a Vercel function.
19. **MediaPipe pinned to 0.10.14** — last line with the legacy `solutions.face_mesh`/`face_detection` API and Python 3.11 wheels for Windows, macOS and Linux.
20. **Training stage order: `export` runs before `handcrafted_features`.** §5.6 lists export as stage 8, but fusion features must include the learned detectors' scores. Running export first lets `handcrafted_features` call the engine's `analyze_file()` with the exact ONNX graphs (and INT8 choices) that will be served, so train/serve features are identical. Stage names and outputs are otherwise as specified.
21. **rPPG uses POS instead of the plain green channel.** §5.2.4 allows "mean green (or POS/CHROM)"; POS (Wang et al. 2017) is markedly more robust to illumination and motion. The indicator catalog and seed describe POS.
22. **INT8 quantisation is gated on labelled validation data.** Dynamic INT8 is kept only when validation AUC drops < 1 pt. `fetch_pretrained.py` (no data available) therefore ships FP32 graphs, including the ~1 GB-class CLIP ViT-L/14 tower, uploaded to Storage in 45 MB parts.
23. **No dataset downloader URLs.** None of the §5.6 dataset sources could be verified as a direct, licence-free download (all are gated by forms/licence pages; search tooling returned nothing usable), so `training/download_datasets.py` only prints acquisition/placement instructions and counts local files, as §0.8 requires.
24. **Seed rows are applied through the SQL editor.** `npx supabase db push` applies migrations but not `seed.sql` on remote projects; the `--include-seed` flag could not be confirmed for every CLI version, so RUN_GUIDE §3 pastes `supabase/seed.sql` in the SQL editor (idempotent upsert) and mentions the flag conditionally. `seed.sql` is generated from the engine's `CATALOG` so UI, PDF and engine text match.
25. **Hugging Face deployment via the Python API (plus a git script).** Commands were verified against `huggingface_hub` 1.32.0 (`hf auth login`, `hf repos create --type space --sdk docker`, `hf spaces secrets add`, `HfApi.create_repo/upload_folder/add_space_secret`). `scripts/deploy_engine.py` creates the Space, sets secrets/variables and uploads `backend/`; `scripts/deploy_engine.sh` is the git-push alternative.
26. **Live session save = Stop.** The Live Monitor's "Stop & create case" both ends capture and aggregates all windows into one case (§7 "Save session"), so a session cannot be left half-saved. Chunks are recorded by restarting MediaRecorder every 3 s so each chunk is an independently decodable WebM; when the engine falls behind real time (> 3 pending windows) new chunks are skipped and counted rather than queued unboundedly.
27. **Landing use-case demos show real or empty states.** The live components inside the use-case cards render a real public-showcase case of the matching media type when one exists; otherwise the gauge renders its empty state with "no public case of this type yet" — no sample numbers.
28. **Server-minted API keys and profile roles.** The migration revokes client `INSERT` on `api_keys` (so users cannot choose their own hash or quota) and limits profile updates to `display_name`/`org`; keys are created by `/api/keys` with the service role.
29. **Quota counts scans only.** `POST /api/v1/analyze` consumes quota; `GET` case/report calls return current `X-RateLimit-*` headers without consuming it.
